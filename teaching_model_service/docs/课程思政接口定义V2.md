# 教学 AI 统一对话接口文档

| 项 | 内容 |
|---|---|
| 接口地址 | `POST /v1/chat/teaching` |
| 路由方式 | 统一入口 + `metadata.chatType` 区分业务 |
| 支持场景 | `case_guide_study`、`lesson_plan_assist` |
| 服务形态 | 无状态，不保存 conversation history |
| 返回形态 | 同时支持流式（SSE）和非流式（JSON） |
| 协议字段 | `content`、`reasoning_content`、`usage`、`error`、`model` |

---

## 0. 一页速览

### 0.1 统一入口

- 所有教学 AI 对话统一调用：`POST /v1/chat/teaching`
- 业务区分字段：`metadata.chatType`

### 0.2 chatType 与业务映射

| chatType | 业务含义 |
|---|---|
| `case_guide_study` | 案例导引学习 |
| `lesson_plan_assist` | 课程思政备课助手 |

### 0.3 关键约束

- 模型服务无状态，不负责存储会话历史。
- `conversationId`、`turnId` 在请求/响应一级字段保留并透传。
- 请求 `stream=true` 返回 SSE；`stream=false` 返回 JSON。
- 未传 `stream` 时默认按 `stream=true` 返回 SSE。

---

## 1. 通用协议约定

### 1.1 请求头

- `Content-Type: application/json`
- `Accept: application/json`（非流式）或 `text/event-stream`（流式），仅作为客户端推荐请求头，服务端不强制校验；服务端以请求体 `stream` 字段为准决定返回格式。
- `Authorization: Bearer <API Key>`

API Key 由成研院后端持有并管理，浏览器前端不直接暴露长期有效 API Key。

### 1.2 请求体（统一结构）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| requestId | String | 否 | 请求唯一标识；为空时服务端自动生成（前缀 `REQ`）。 |
| conversationId | String | 否 | 会话标识；为空时服务端自动生成（前缀 `CNV`）。 |
| turnId | Integer | 是 | 当前轮次，最小值 `1`。 |
| messages | Array<ChatMessage> | 是 | 对话消息列表（至少 1 条，最后一条为本次用户消息）。 |
| metadata | Object | 是 | 业务元数据，且 `metadata.chatType` 为业务必填字段。 |
| stream | Boolean | 否 | 是否流式返回，默认 `true`。 |
| model | String | 否 | 请求期望模型标识；传入时用于本次请求，未传入时使用服务端 `ZHIPU_MODEL` 配置，默认 `glm-5.2`。 |

`ChatMessage`：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| role | String | 是 | 取值见下表（不开放 `SYSTEM`） |
| content | Array<ContentItem> | 是 | 内容数组，至少 1 条 |

`role` 取值：

| role | 说明 |
|---|---|
| `USER` | 用户输入 |
| `ASSISTANT` | 助手回复 |

`ContentItem`（当前版本）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| type | String | 是 | 固定 `TEXT` |
| text | String | 是 | 文本内容 |

## 2. 业务字段规范（metadata）

### 2.1 案例导引学习（`case_guide_study`）

> 案例内容由调用方提供，直接拼接在 `messages` 中传入；模型服务不负责案例资源管理。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| chatType | String | 是 | 固定 `case_guide_study` |
| schoolLevel | String | 是 | 学段 |
| subject | String | 是 | 学科 |
| textbookVersion | String | 是 | 教材版本 |
| chapter | String | 是 | 章 |
| lesson | String | 是 | 节 |

### 2.2 课程思政备课助手（`lesson_plan_assist`）

> 该 `chatType` 统一承载教案生成与教案修改/思政融合。
> 修改场景的原教案内容由上游拼接进 `messages`，元数据结构保持一致。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| chatType | String | 是 | 固定 `lesson_plan_assist` |
| schoolLevel | String | 是 | 学段 |
| subject | String | 是 | 学科 |
| textbookVersion | String | 是 | 教材版本 |
| chapter | String | 是 | 章 |
| lesson | String | 是 | 节 |
| knowledgePoints | Array<String> | 否 | 知识点列表（建议数组） |

---

## 3. 统一响应协议

### 3.1 响应顶层字段

| 字段 | 类型 | 必有 | 说明 |
|---|---|---|---|
| requestId | String | 是 | 请求标识，与请求对应 |
| conversationId | String | 是 | 会话标识 |
| turnId | Integer | 是 | 当前轮次 |
| model | String/Null | 是 | 实际使用模型；可为 `null` |
| l1_labels | Array<String> | 是 | 一级思政标签列表；可为空数组 |
| content | String | 是 | 输出内容；非流式为完整正文，流式为当前增量 |
| reasoning_content | String/Null | 是 | 智谱返回的模型思考过程；非流式为完整内容，流式为当前量 |
| finishReason | String/Null | 是 | 结束原因；结束为 `stop`，未结束为 `null` |
| usage | Object/Null | 是 | token 使用量；流式通常在结束片段返回 |
| error | Object/Null | 是 | 错误信息；成功时为 `null` |

字段语义：

- `lesson_plan_assist`：`content` 只返回生成或修改后的 Markdown 教案；`reasoning_content` 返回中文、可展示的教材分析、教案对齐、思政标签匹配等模型思考过程。
- `case_guide_study`：只返回案例导引内容，`reasoning_content` 固定为空字符串；
- `reasoning_content` 在协议层允许为字符串或 `null`。上游未提供推理内容时，服务端可以返回 `null`；案例导引按本业务约定返回空字符串。
- 课程思政备课助手接口返回的`content` 由调用方自行交给 Markdown 渲染器处理。

`usage` 结构：

| 字段 | 类型 | 必有 | 说明 |
|---|---|---|---|
| inputTokens | Integer | 是 | 输入 token 数 |
| outputTokens | Integer | 是 | 输出 token 数 |
| totalTokens | Integer | 是 | 总 token 数 |

`error` 结构：

| 字段 | 类型 | 必有 | 说明 |
|---|---|---|---|
| code | String | 是 | 错误码（如 `INVALID_ARGUMENT`） |
| message | String | 是 | 错误描述 |
| retriable | Boolean | 是 | 是否可重试 |

## 4. 流式与非流式返回

### 4.1 流式返回（`stream=true`）

- HTTP：`200 OK`
- Content-Type：`text/event-stream`
- 事件名：`event: message`
- 载荷：`data: <JSON字符串>`

推理内容增量示例：

```text
event: message
data: {"requestId":"REQ20260902000001","conversationId":"CNV20260902000001","turnId":1,"model":"glm-5.2","l1_labels":["责任担当"],"reasoning_content":"已完成教材分析。","content":"","finishReason":null,"usage":null,"error":null}
```

Markdown 教案增量示例：

```text
event: message
data: {"requestId":"REQ20260902000001","conversationId":"CNV20260902000001","turnId":1,"model":"glm-5.2","l1_labels":["责任担当"],"reasoning_content":"","content":"# 课程思政教学设计","finishReason":null,"usage":null,"error":null}
```

结束事件示例：

```text
event: message
data: {"requestId":"REQ20260902000001","conversationId":"CNV20260902000001","turnId":1,"model":"glm-5.2","l1_labels":["责任担当"],"reasoning_content":"","content":"","finishReason":"stop","usage":{"inputTokens":1580,"outputTokens":920,"totalTokens":2500},"error":null}
```

### 4.2 非流式返回（`stream=false`）

- HTTP：`200 OK`
- Content-Type：`application/json`

```json
{
  "requestId": "REQ20260902000001",
  "conversationId": "CNV20260902000001",
  "turnId": 1,
  "model": "glm-5.2",
  "l1_labels": ["责任担当"],
  "reasoning_content": "已完成教材分析、教案对齐和思政标签匹配。",
  "content": "# 课程思政教学设计\n...",
  "finishReason": "stop",
  "usage": {
    "inputTokens": 1580,
    "outputTokens": 920,
    "totalTokens": 2500
  },
  "error": null
}
```

## 5. 错误响应规范

参数校验失败、业务类型不支持或服务异常时：

- HTTP：`4xx/5xx`
- Content-Type：`application/json`
- `finishReason` 返回 `error`。
- `content` 和 `reasoning_content` 返回空字符串。

```json
{
  "requestId": "REQ20260902000001",
  "conversationId": "CNV20260902000001",
  "turnId": 1,
  "model": null,
  "l1_labels": [],
  "reasoning_content": "",
  "content": "",
  "finishReason": "error",
  "usage": null,
  "error": {
    "code": "INVALID_ARGUMENT",
    "message": "metadata.chatType is required",
    "retriable": false
  }
}
```

## 7. 兼容性与版本说明

- 本文档为统一接口 V2（0902 输出结构调整版）。
- 旧版若存在 `knowledgePoints` 以 JSON 字符串传递，建议升级为 `Array<String>`。
- 未声明字段默认不作为协议保证项。
- 当前版本不提供 `outputType`、`outputs` 或 `stage` 字段；调用方应使用 `content`、`reasoning_content`、`finishReason`、`usage` 和 `error`。
- `/health/ready` 就绪时返回 HTTP 200，依赖未就绪时返回 HTTP 503。
- `MODEL_BACKEND` 仅支持 `mock` 和 `zhipu`；未显式关闭鉴权时，API Key 校验默认启用。
