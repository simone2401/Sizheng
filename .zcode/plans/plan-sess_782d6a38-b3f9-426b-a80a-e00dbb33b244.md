1. 统一运行时配置
   - 修改 `app/model_api/main.py` 和 `app/resource_api/main.py`，使每个应用只在 lifespan 中创建一份 settings，并保存到 `app.state.settings`。
   - CORS 配置、路由 settings 依赖、模型/资源服务初始化统一使用这份配置，避免导入时配置和启动时配置不一致。
   - 保留 FastAPI 测试中的 dependency override 能力；为没有进入 lifespan 的场景提供清晰的未初始化错误。
   - 增加或调整健康检查、鉴权和配置覆盖测试，确认实际使用的是同一配置。

2. 消除最新教师请求重复注入
   - 修改 `app/model_api/teaching_service.py` 的对话文本构造逻辑。
   - `【对话记录】` 只保留最新消息之前的历史消息；`【教师当前请求】` 只保留最后一条 USER 消息。
   - 保持历史消息顺序、USER/ASSISTANT 标记和原教案提取行为不变。
   - 增加测试，明确断言最后一条消息只出现在当前请求区块，不再出现在历史记录区块。

3. 在资源客户端边界校验统一资源契约
   - 修改 `app/model_api/resource_client.py`，成功响应通过 `ResourceResponse.model_validate()` 解析，并将校验失败映射为 `ResourceUnavailableError`。
   - 保持对 404 的 `ResourceNotFoundError` 映射；区分资源服务鉴权失败/客户端参数错误与可重试的上游不可用错误，避免所有 4xx 都被错误标成 503。
   - 在 `teaching_service.py` 中使用契约模型的字段或统一序列化结果，减少裸字典结构依赖；同时兼容资源 API 的 camelCase aliases。
   - 增加资源客户端成功、无效 JSON、契约缺字段、404、401/5xx 的测试。

4. 扩展模型结束原因兼容性

   - 对未知值保持明确的 `MODEL_RESPONSE_INVALID`，不静默吞掉异常。
   - 确保非流式和流式路径都能正确透传合法结束原因，流式终止事件只发一次。
   - 增加各结束原因以及未知结束原因的单元测试，并同步更新接口文档中的允许值说明。

5. 完善 SSE 稳定性和上游兼容

   - 保持 `event: message` 业务事件格式不变，并补充空 choices、`[DONE]`、长等待/keepalive 的测试。
